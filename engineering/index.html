Anatomy of an agent

What I built, piece by piece.

Users & channels

Staff chat with agents, build their own custom agents, and run departmental workflows that were turned into agents.

~1,300 weekly active users

Guardrails

Prompt-injection screening, human approval for write actions and a memory safety gate. A governance gateway applies egress allowlists, usage limits and audit logs to every tool, retrieval and web call.

access by department, grade and directory group

Agent harness

A provider-neutral streaming agent loop: tool calling, orchestration and sub-agent delegation. Every tool round streams. History trimming, tool-result compaction and cross-provider prompt caching keep context lean.

88% cache hits · 75% lower input cost · 40% faster first token

MCP connectors

Model Context Protocol connectors for Microsoft 365, Atlassian and more, with per-user OAuth, an encrypted credential vault and approval before any write.

RAG & SQL analysts

Retrieval over agent-scoped knowledge bases. Analyst agents run text-to-SQL through a read-only, row-capped query layer, so they answer business questions without ever changing data.

Long-term memory

Extracts, reconciles and safety-checks per-user memories, so agents carry useful context across conversations.

Code sandbox

Warm pools of network-isolated Kubernetes pods where agents run code to produce Office documents, PDFs and interactive web artifacts.

Model routing

Routing and fallback chains live in the database, so a model can be swapped or failed over without a redeploy. High-volume work runs on on-prem models.

Control plane

Hot-reloads models, agents, prompts and access rules without redeployment.

Evals & observability

An LLM-as-a-judge harness across models with versioned prompts and tool schemas, plus automated tests, CI gates and Grafana dashboards on time to first token, tool errors and spend.

35% fewer failed turns
