anatomy of an agent

request path

users & channels

staff chat with agents, build their own custom agents, and run departmental workflows that were turned into agents.

~1,300 weekly active users

guardrails

prompt-injection screening, human approval for write actions and a memory safety gate. a governance gateway applies egress allowlists, usage limits and audit logs to every tool, retrieval and web call.

access by department, grade and directory group

agent loop

the agent loop is provider-neutral and streams every tool round. it handles tool calling, orchestration and sub-agent delegation. history trimming, tool-result compaction and cross-provider prompt caching keep the context short.

88% cache hits · 75% lower input cost · 40% faster first token

MCP connectors

model context protocol connectors link agents to microsoft 365, atlassian and other services. each user signs in with their own OAuth account. credentials sit in an encrypted vault, and every write needs approval.

RAG & SQL analysts

each agent retrieves from its own knowledge base. analyst agents run text-to-sql through a read-only, row-capped query layer, so they answer business questions and cannot change data.

long-term memory

the memory service extracts, reconciles and safety-checks memories for each user. agents keep that context across conversations.

code sandbox

agents run code in warm pools of network-isolated kubernetes pods. the code produces office documents, PDFs and interactive web artifacts.

model routing

the database stores routing and fallback chains, so i can swap or fail over a model without a redeploy. high-volume work runs on on-prem models.

control plane

the control plane hot-reloads models, agents, prompts and access rules without a redeploy.

evals & observability

an LLM-as-a-judge eval suite tests each model against versioned prompts and tool schemas. the platform also has automated tests, CI gates and grafana dashboards for time to first token, tool errors and spend.

35% fewer failed turns
